# DESIGN_04 — 분석 대상 자동감지 (설계)

> 상태: 설계 확정(구현 전). 로드맵 3번. 설치 시 "제품/모듈 수동 선택" 제거 → 데이터 감지로 자동 on/off.

## 0. 문제
- OWL은 여러 도메인을 분석(반출, 개인정보 오남용, … 앞으로 확장). 고객사마다 쓰는 채널·보유 데이터가 다름.
- 옛 방식: 설치 시 관리자가 분석 모듈을 **수동 선택** → 귀찮고 오류(데이터 없는 모듈 켜기 / 있는 것 누락).

## 1. 자동감지 방식 [확정]
- OWL이 고객 데이터를 스스로 검사해 **데이터가 있는 모듈만 자동 활성.**
- **판정 기준: 테이블 존재 + 최근 데이터 (옵션 ③).**
  - 테이블만 있고 비었으면 안 켬. 실제 데이터가 있어야 함.
- **"최근" = 최근 30일.** 지난 30일 내 로그가 하나라도 있으면 = 살아있는 채널 → 켬.
  - 근거: 너무 짧으면(예: 3일) USB처럼 저빈도지만 중요한 채널을 잘못 끔. 너무 길면(예: 6개월) 죽은 채널까지 켜서 헛분석. **30일이 균형.**

## 2. 동작 [확정]
1. **도메인 카탈로그** — 모듈 ↔ 로그 테이블 ↔ recipe 매핑(어떤 분석이 어떤 로그를 보는지).
2. OWL이 **매일 1회** 카탈로그대로 각 로그를 확인 → 최근 30일 데이터 있으면 on, 없으면 off.
3. **자기조정(self-adjusting):** 채널이 막혀 로그가 30일 끊기면 자동 off, 새 채널 생기면 자동 on. 관리자 수동 개입 불필요.
4. **부분 가용 graceful:** 일부 채널만 있어도 있는 것만 켜져 정상 동작.

## 3. 확인 필요
- 도메인 카탈로그(모듈↔테이블 매핑) 정의 목록.
- 재확인 주기(기본 매일)·"최근 30일" 파라미터는 config로 조절 가능하게.

## 참고 (확정 요약)
- 자동감지 = 테이블 존재 + 최근 30일 데이터 → 있는 것만 자동 on/off
- 매일 재확인 · self-adjusting · 부분 가용 graceful
