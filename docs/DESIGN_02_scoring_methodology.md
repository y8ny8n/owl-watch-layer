# DESIGN_02 — 채널교차·행동기반 스코어링 개선 (설계)

> 상태: 설계 확정 (구현 전). 사용자와 대화하며 정한 결정 기록.
> 핵심 철학 재확인: OWL은 파일 내용의 "기밀 분류"에 의존하지 않고 **행동**으로 중요도+의도를 판단한다. (PCFILTER에 기밀 분류가 없다는 점이 오히려 OWL이 필요한 이유 — 기존 DLP는 분류된 것만 보지만 OWL은 분류 안 된 것도 행동으로 잡는다.)

## 1. 행동 기반 중요도 판단

파일이 "중요한지"를 미리 알 필요 없이, 사람이 그 파일을 **어떻게 다루는지**로 판단한다.

### ① 숨기는 행동 = "이 파일이 중요하다"는 증거
(안 중요한 파일은 안 숨긴다. 숨긴다는 것 자체가 중요하다는 뜻.)
- 이름·확장자 바꾸기 (S1) — 예: `영업기밀.xlsx` → `사진.jpg`
- 압축 (S2)
- **검사회피** (S3) — PCFILTER가 내용을 못 보고 통과시킨 표시
  - 확인 결과: PCFILTER는 암호 걸린 파일을 **(A) 기록 후 통과**시킨다. `is_block=false` + `hash_extract_fail_reason` 필드에 사유 기록. 값: `password_protected_archive` / `encrypted_zip` / `encrypted`.
  - 정의: **"암호 걸었다" 자체가 아니라 "PCFILTER가 검사 못 하고 통과시킨 표시가 있을 때"**를 신호로 본다. (암호 자체는 정상 업무일 수 있으므로.)
- 원칙: ①이 **하나라도 있으면 "중요 파일로 취급"**

### ② 반출 행동 = "밖으로 나가는 중"이라는 증거
- 야간·주말 (S6)
- 여러 경로 동시 + 같은 파일 (S7 — 아래 2절에서 개선)
- 생성형 AI에 붙여넣기 (S8)
- 조금씩 여러 번 나눠서 (S9, low-and-slow)
- **(제외됨) "비공식 경로"**: 신호로 안 쓴다. 비인가 채널·USB는 PCFILTER가 이미 차단하므로 허용 로그에 안 남는다. OWL은 허용된 회색지대만 본다. → 채널은 "공식이냐"가 아니라 **"어떻게 쓰냐"**로 본다.

## 2. 채널교차(S7) 개선 — 단순 카운트 탈피, 3단계

기존: "수상한 채널 2개 이상이면 교차" 단순 카운트 → 시점 무관하여 오탐(월요일 메일 + 3주 뒤 USB도 교차로 잡힘).

- **1단계 — 시간 근접:** 여러 채널을 **같은 날(시간 근접)** 안에 썼을 때만 교차 인정. (결정: 기준 = "같은 날". 더 빡빡하게(몇 시간)도 가능하나 우선 같은 날.)
- **2단계 — 같은 파일:** 같은 *핵심* 파일이 여러 경로로 나갈 때 = 가장 확실한 증거 (더 높은 확신/점수). 
  - 확인필요: 파일 식별. 이름은 위장 가능(S1) → 해시 등 안정 식별자가 로그에 있는지 실로그 확인 필요.
- **3단계 — 킬체인(순서):** 준비(이름위장→압축→암호화) → 반출 의 **순서 패턴**을 잡음. 발표 하이라이트. **(방법 A로 확정 — 아래 '2-A절' 상세)**

## 2-A. 킬체인 지속추적 — 방법 A (감시 항목 기반) [확정]

**방식: 방법 A (앞으로 추적).** 숨김이 감지되는 순간 "감시 항목"을 열고, 반출이 일어날 때까지 **앞으로 따라간다.** (반출 시점에 과거를 되짚는 방법 B가 아님 — 사용자가 A를 선택.)

**동작:**
1. 숨김 행동(① 이름위장·압축·검사회피) 감지 → **감시 항목(watch) 생성.**
   - 필드: `agent`(사람), `file_ref`(파일 식별자), `opened_at`, `expires_at`(기본 opened_at + 7일), `status`(open/matched/expired), `admin_pinned`(bool)
2. 반출 행동(②) 감지 → 열린 감시 항목과 대조(같은 사람/파일) → 매칭되면 `status=matched`, **"숨김→반출" 킬체인 완성 → 고위험 승격.**
3. `expires_at` 경과 시 자동 만료(`status=expired`). 반출 없이 끝난 숨김은 닫힘.

**기본 추적 기간 = 7일.**

**관리자 "지속 관찰" (에스컬레이트 레버):**
- 관리자가 리포트에서 "지속 관찰" 지정 → 해당 감시 항목 `admin_pinned=true` → **만료 없이(또는 훨씬 길게) 연장.**
- 관찰 대상 = **사람 + 파일 둘 다.** (그 파일만이 아니라 다른 파일도 빼돌릴 수 있으므로 사람도 넓게 감시 — 그물을 넓힘.)
- 이는 목적지 화이트리스트("괜찮아 → 억제")와 **대칭인 에스컬레이트 레버**("계속 지켜봐 → 연장"). 관리자는 억제/증폭 두 방향으로 조절.
- 관리자는 "현재 감시 중 목록"을 조회 가능(대시보드/발표 자산).

**의존성/주의:**
- 파일 단위 추적은 **안정 식별자(해시)** 필요 → 2절 "확인 필요" 항목. 해시 확보 전까진 **사람 단위 추적만으로도 동작**(파일 추적은 해시 확인 시 완성).
- A는 **감시 항목 상태(watch 테이블 + 생명주기: open/match/expire)**가 새로 필요 — 분석 루프에 로직 추가. 방법 B보다 구현량은 늘지만 "끝까지 쫓는다" 모델과 관리자 지속관찰에 정확히 부합.

## 3. 목적지 화이트리스트 (오탐 피드백 루프)

관리자가 리포트를 보고 **"이 목적지는 괜찮아"** 표시하면, 이후 분석에서 그 목적지로의 반출은 점수를 **감점(확 낮춤)**한다.

- **단위: 목적지 기준** ("누구"보다 "어디로 가느냐"가 핵심). 사람별 규칙보다 단순하고, 관리 부담 적음.
- **안전장치:** 점수를 **0으로 만들지 않고 "확 낮춤"** — 평소 괜찮던 목적지라도 다른 수상 행동(①숨김 등)이 겹치면 다시 떠야 하므로.
- **승인 목적지 악용 주의:** 회사 공식 드라이브(승인됨)에 대량 반출 같은 악용은 목적지 화이트리스트로 눈감지 말고 **"대량 반출" 등 다른 신호로 커버**한다.

### 채널별 목적지 필드 (원문 PCFILTER API 스펙 확인 결과)
| 채널 | 목적지 필드 | 화이트리스트 |
|---|---|---|
| 웹 업로드(website) | `host_url` / `sub_url` (사이트 주소) | ✅ 가능 |
| 클라우드/웹하드(fileattach cat.7) | `browser_url` (주소) | ✅ 가능 |
| 공유폴더(sharedfolder) | `file_path` (목적지 경로) | ✅ 가능 |
| ChatGPT | `url` / `type` (서비스) | ✅ 가능 |
| **USB(media)** | `device_parent_id`(시리얼)·`device_description`(장치명)·`volume_id` | ✅ 가능 (기기 단위) |
| **메일 클라이언트(fileattach cat.6)** | 수신자 정보 **없음** (원문 로그에도 없음) | ❌ 불가 |

- 구현 메모: 현재 `exfil.py`는 이 목적지 필드들을 아직 SELECT 안 함 → 화이트리스트 구현 시 쿼리에 컬럼 추가 필요.

## 4. 메일 예외 처리 — 수신자 못 잡음 → 시간으로 대체

메일은 목적지(수신자)를 알 수 없으므로 **"어디로" 대신 "언제 + 어떻게"**로 판단:
- **업무시간 내 + 평범한 파일** → 낮은 점수 (정상, 안 띄움)
- **업무시간 외(야간·주말)** → 시간 점수 부여
- **업무시간 내여도 ①숨기는 행동/대량 개인정보가 겹치면** → 겹침(신뢰)으로 떠오름
- 즉 낮에 몰래 빼도 파일을 위장·암호화했다면 ①이 잡는다.

## 5. 확인 필요 (제품화 전 실로그 대조)
- `hash_extract_fail_reason` 필드명·값·`is_block` 동작이 데모와 실서버가 동일한지 (현재 근거는 데모 시드+원문 스펙).
- 2단계(같은 파일)용 **안정 파일 식별자(해시)**가 로그에 있는지.
- (해결됨) 메일 수신자 필드 없음 / USB 기기ID(`device_parent_id`) 있음 — 원문 API 스펙(`pcfilter_work/.claude/api-spec`)으로 확인 완료.

## 6. 스코어링 가중치 근거 (a) [확정]

가중치는 감이 아니라 **두 질문**으로 정한다:
1. **은폐 의도가 센가?** (대놓고 숨기고 우회할수록 ↑)
2. **정상 업무에 흔한가?** (흔하면 오탐 위험 → ↓)
→ **"은폐 의도 세고 + 정상 업무엔 드문"** 행동일수록 높은 점수. (MITRE ATT&CK류 위협 프레임워크로도 근거 제시 가능.)

| 신호 | 은폐의도 | 정상업무 흔함 | 점수 |
|---|---|---|---|
| 채널교차 | 상 | 매우 드묾 | 30 |
| 이름 위장 | 상 | 드묾 | 25 |
| 지속 반복 | 상 | 드묾 | 25 |
| 검사회피(암호) | 상 | 보통 | 20 |
| 생성형AI 붙여넣기 | 상 | 드묾 | 20 |
| 스크린샷 급증 | 상 | 급증은 드묾 | 20 |
| 개인정보 대량 | 중 | 보통 | 15 |
| 압축 | 중 | 흔함 | 15 |
| 야간·주말 | 하 | 보통 | 10 |

참고: 이 기준으로 매긴 결과가 기존 감으로 정한 가중치와 거의 일치 → 기존 값에 "왜(근거)"를 부여한 것. 심사 방어용: "왜 30점?" → "채널교차는 은폐의도 최상 + 정상 업무엔 거의 없어서".

## 7. 신규 신호 — 스크린샷 급증 [확정]

- **배경(스크린샷 유출):** 문서를 화면캡처(이미지)로 찍으면 PCFILTER가 안의 내용을 못 읽는다(검사 회피 계열 — 암호와 같은 원리). 내용 판별 불가 → **행동(급증)으로 판단.**
- **로그 근거:** 전용 캡처 로그 `dlp_capture_log`(`log_dlp_capture_t`)가 스크린샷/프린트스크린을 직접 기록. 필드: `process`(예: `SnippingTool.exe` / `Print Screen`), `log_time`, `agent_id`, `mac`. 백업: 프로세스 로그 `dlp_process_log`의 `category=9(화면캡처)`.
- **탐지 규칙:** 같은 `agent_id`가 **짧은 시간창(기본 10분) 안에 10장 이상** 캡처 → "급증". (장수가 많을수록 점수 가산 가능: 10장=기본, 30장=더 위험.)
- **점수: 20점** (검사회피 계열, 암호·AI와 동급). 혼자선 알림 못 띄우고 겹칠 때만 위험으로 승격.
- **오탐/놓침 처리:**
  - 업무용 다량 캡처(오탐) → "겹침=신뢰"로 흡수(혼자 20점은 안 뜸, 다른 수상 신호와 겹칠 때만).
  - 2~3장 소량 캡처(급증 미달) → 아래 8절 "캡처→반출"로 커버.
- **정책 의존성(주의):** 캡처 로그는 **"화면캡처 관리 정책(`set_capture_manage`, `block_print_scrn`/`block_capture_process`)"이 켜진 단말에서만** 생성됨. 정책 꺼진 PC는 캡처해도 로그가 안 남음 → 전제: 대상 단말에 정책 켜두기.
- **임계값(10분/10장)은 시작값** — 실제 캡처 로그로 평소 캡처율을 보고 캘리브레이션 필요(우선 오탐 안 나게 보수적으로).

## 8. 캡처 → 반출 (보조 탐지) [확정]

급증(대량 촬영)으로 못 잡는 **소량(2~3장) 캡처**를 커버: 찍은 스크린샷 **이미지가 밖으로 나가면**(메일·USB·클라우드) 반출 행동(②)이 잡는다. 장수 무관. 즉 스크린샷은 두 갈래로 촘촘히 본다 — **급증(대량 촬영) + 캡처→반출(소량 포함).**

### (2절/5절 "확인 필요"에 추가) 
- 스크린샷 급증 임계값(10분/10장) 실데이터 캘리브레이션.
- 대상 단말에 화면캡처 관리 정책이 실제로 켜져 있는지(안 켜지면 캡처 로그 미생성).

## 참고 (이번 세션에서 확정한 것 요약)
- 시간 근접 기준 = **같은 날**
- 화이트리스트 단위 = **목적지 기준** (점수 0 아닌 감점)
- 메일 = 시간 기반 + ①겹침으로 커버
- "비공식 경로" 신호 제외, "암호" = 검사회피 표시로 재정의
- 킬체인 = **방법 A(감시 항목 → 반출 매칭)**, 기본 추적 **7일**
- 관리자 레버 2개: **"괜찮아"(목적지 억제) ↔ "지속 관찰"(사람+파일 추적 연장)**
- 지속 관찰 대상 = **사람 + 파일** (파일 추적은 해시 확인 시 완성)
- 가중치 = **두 질문(은폐의도/정상업무 흔함)** 기반 근거화 (기존 감과 거의 일치, "왜"를 부여)
- 신규 신호 **스크린샷 급증 = 20점** (전용 `dlp_capture_log`, 10분/10장 시작값, 정책 켜짐 전제)
- 스크린샷 두 갈래: **급증(대량) + 캡처→반출(소량)**
