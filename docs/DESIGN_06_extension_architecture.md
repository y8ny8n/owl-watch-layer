# DESIGN_06 — MCP·확장 아키텍처 (설계)

> 상태: 설계 확정(구현 전). 로드맵 6번. OWL = "모든 근거로 파악하는" 판단 두뇌. 확장성을 기본으로.

## 0. 비전
- OWL은 PCFILTER 전용이 아니라 **여러 근거(신호)를 모아 사람 위험을 판단하는 두뇌.**
- PCFILTER는 신호 **공급원 중 첫 번째**일 뿐. 다른 보안 도구(다른 DLP·EDR·SIEM 등)도 신호를 push하면 동일 채점.

## 1. 확장 구조 [확정]
- OWL 내부에 **"신호 공통 입구"**를 둠. 각 도구는 그 입구에 신호를 넣는 **어댑터**.
- PCFILTER = 첫 어댑터. 새 도구 = 어댑터 하나 추가. **채점·AI·정책 로직은 출처 무관하게 그대로.**
- "근거 공급원은 늘어나되, 판단 두뇌는 하나."
- 전송/수신 인터페이스: **MCP 또는 공통 API**로 외부 도구가 정규화 신호 push. (MVP는 "확장 예정" 안내, 아키텍처는 지금 설계.)

## 2. 표준 신호 형식 [확정 — 우선 다 넣고, 붙여보며 과한 칸은 뺀다]
| 칸 | 의미 |
|---|---|
| 누가 | 행위자(사람/에이전트) 식별 |
| 언제 | 시각 |
| 무슨 행동 | 신호 유형(이름위장·대량조회·스크린샷급증 등) |
| 얼마나(증거) | 크기·개수·요약 |
| 어느 출처 | 도구 + 채널 |
| ➕ 원본 참조 | 원본 로그/증거로 가는 ID·링크(관리자 조사·검증용) |
| ➕ 차단/허용 상태 | blocked vs allowed (OWL은 허용된 회색지대 중심) |
| ➕ (선택) 신뢰도 | 출처가 매긴 확신도 |
| ➕ 스키마 버전 | 표준 진화 대비 호환 |
| ➕ 자유 칸(extra) | 도구별 특이 정보 담는 확장 필드 |

## 3. 관점별 보강 (관리자 / 업체 / 해커 red-team)
- **보안 관리자:** 원본 참조·상태값으로 실제 조사·대응이 가능하게.
- **업체(도구 공급사):** 버전 + 자유 칸으로 어떤 도구든 맞춰 보내기 쉽게.
- **해커(핵심):**
  - **가짜 신호 주입 차단** — **인증된 출처만 push + 신호 서명(위변조 방지).** (무고한 사람 모함, 노이즈로 진짜 숨김 방지)
  - **신호 침묵 감지** — 원래 신호가 나오던 출처가 갑자기 조용해지면 → 이상 감지(자동감지 self-adjusting 재사용).
  - **신원 위조** — "누가" 칸의 신뢰성 확보 필요(향후 과제).

## 4. 확인 필요 / 스탠스
- **"우선 다 넣고, 실제 붙여보며 과한 칸은 뺀다"**(사용자 결정).
- MCP vs 자체 공통 API 중 전송 방식 확정.
- 출처 인증·서명 방식(키/토큰 등) 구체화.
- 신원 위조 대응은 향후 과제.

## 참고 (확정 요약)
- OWL = 모든 근거로 판단하는 두뇌, 확장성 기본(공통 입구 + 어댑터, PCFILTER=첫 어댑터)
- 표준 신호 = 누가/언제/무슨행동/얼마나/출처 + 원본참조·상태·버전·자유칸 (+ 출처 인증·서명)
- 해커 시점: 가짜 주입 차단(인증+서명), 침묵 감지
