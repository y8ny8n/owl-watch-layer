# DESIGN_03 — 개인정보 오남용 recipe (설계)

> 상태: 설계 확정(구현 전). 사용자와 대화하며 정한 결정.
> 로드맵 2번 — 첫 도메인 확장(확장성 증명). exfil(반출) recipe와 별개 도메인.

## 0. 개념 — 반출과 다른 각도
- 기존 exfil recipe = **"파일이 회사 밖으로 나가는 것"**.
- 개인정보 오남용 = 파일이 안 나가도, **개인정보에 "접근·사용하는 방식" 자체가 수상한 것.**
- PCFILTER가 개인정보를 이미 분류(개인정보 태그 존재; 기밀은 없어도 개인정보는 있음) → 바탕 데이터가 있어 확장 1순위.

## 1. 오남용 신호 (핵심)
- **대량 조회** — 짧은 기간에 서로 다른 대상 다수의 개인정보 조회. ⚠️ 직군별 정상범위 다름(2·4절).
- **목적 외 열람 / 특정 타인 집요 조회**
  - 남 여러 명 대량 = 대량 조회.
  - **남 한 명을 업무 이유 없이 집요하게 반복** = 스토킹성(전 애인·연예인 등). 실제 사고 단골.
  - (권한 밖 열람 = 자기 직무 밖 데이터 접근 → 여기 묶음. 역할/권한 컨텍스트 필요 → 6절 확인필요.)
- **이상 시간 조회** — 야간·주말 등 비정상 시간대 접근(반출 S6 개념 재사용).
- **조회 후 반출** — 개인정보 대량 조회 → 이어서 반출(오남용+exfil 복합, 킬체인 방식으로 엮임).

## 2. 예외 / 오탐 처리
- **본인 정보 조회 = 예외.** 같은 대상 하나만 반복 = 보통 자기 것(급여·인사) → 제외.
  - 단, 그 "하나"가 본인이 아니라 특정 타인이면 → 위 스토킹성 의심. **본인/남 구분이 관건.**
- **직군별 정상범위** — 콜센터·정산·CS는 대량조회가 정상. → **AI 분석 단계 + 화이트리스트로 "이 직군/이 활동은 정상" 확인 처리**(억제 레버 재사용).

## 3. 핵심 구분축
**본인이냐 남이냐 + 몇 명이냐(대량/집요) + 직무 권한 안이냐.**
- 본인 = 예외 · 남 다수 대량 = 의심 · 남 한 명 집요 = 의심(스토킹) · 직무 밖 = 의심(권한 밖)

## 4. 다른 약점 triage (검토 결과)
- **점진 수집(천천히 모으기):** 별도 불필요 — 결국 **반출 시 잡히고** 개인정보가 한 곳에 모임(exfil 커버).
- **인쇄 유출:** PCFILTER **출력물 관리** 기능이 커버.
- **직군 오탐:** AI 확인 + 화이트리스트로 처리(2절).
- **퇴사 임박:** 5절.

## 5. 퇴사 임박 = 위험 증폭기 (확장 로드맵)
- **별도 탐지기 아님.** 퇴사자의 위험 행동(대량조회·반출 등)은 **기존 신호가 이미 잡음** → 커버 공백 없음("퇴사" 라벨만 없을 뿐).
- "퇴사 임박" 정보는 **점수 배수(부스터)** 역할 — 이미 수상한 활동의 점수를 키움. 예: 40점(관심) → 60점(위험).
- 데이터원: HR 연동(A)이 정확하나 **PCFILTER 본체에 HR 연동 기능이 아직 없음(향후 개발 필요).** → 지금은 **연동 hook(점수 배수 로직의 자리)만** 만들고, PCFILTER가 HR을 붙이면 자동 활성. 그때까진 다른 신호가 행동 커버.
- 행동 추정(B)은 노이즈 많아 현재 미채택.

## 6. 확인 필요 (실로그/제품 확장 대조)
- 개인정보 접근 로그(예: `log_privacy_protect_t`)에 **"조회자(직원) + 조회 대상(누구 정보)" 식별자가 둘 다 있는지** — 본인/남 구분에 필수.
- "권한 밖 열람" 판정용 **직무/역할 권한 정보**가 있는지(없으면 PCFILTER 확장 필요).
- 직군별 정상범위 기준(콜센터 등) 정의.
- 퇴사 임박 HR 연동 = PCFILTER 향후 개발 의존.

## 참고 (이번 세션 확정 요약)
- 개인정보 오남용 = 접근·사용 방식이 수상(반출과 별개 도메인)
- 신호: 대량조회 / 목적외·특정타인 집요 / 이상시간 / 조회후반출
- 예외: 본인 조회 / 직군별 정상범위(AI·화이트리스트)
- 퇴사 임박 = 위험 증폭기(hook만, HR 연동 시 활성 — PCFILTER 확장)
