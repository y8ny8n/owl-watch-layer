# DESIGN_05 — AI 프로바이더 추상화 + 무유출 마스킹 (설계)

> 상태: 설계 확정(구현 전). 로드맵 4번.

## 0. 배경 / 딜레마
- OWL은 현재 로컬 AI(Ollama/Gemma) 사용 → **데이터 무유출**이 최대 셀링포인트("우리는 ClosedAI").
- 일부 고객사는 **사내 LLM** 또는 **외부 클라우드 AI**(Claude/GPT 등)를 쓰고 싶어함(품질·기존 자산).
- 딜레마: 외부 클라우드 AI = 데이터가 서버 밖으로 나감 → 무유출 약속과 충돌.

## 1. 제품 철학 [확정]
- **다양성 제공:** 프로바이더 선택 가능(로컬 Ollama / 사내 LLM / 외부 클라우드).
- **기본값 = 로컬(무유출).** 아무것도 안 나감. 권장/플래그십.
- **외부 = 고객의 informed 선택, 유출 리스크는 고객 책임.** 강요 안 함.
- **단, 무책임하게 열지 않음 — 외부로 나갈 땐 OWL이 노출을 최소화(안전장치).**

## 2. 불변식 [확정]
- **AI는 어떤 프로바이더든 "원본 로그"를 절대 못 본다.** 입력은 항상 **집계된 신호(signals_json)** — 이미 판단이 끝난 요약 재료. (로컬 AI조차 원본 미열람.)
- AI 역할은 signals_json → 사람 말 서술뿐. 최종 정책 JSON은 코드가 조립(환각 0, 기존 원칙).

## 3. 외부 전송 시 마스킹 [확정]
외부 프로바이더로 보낼 땐 signals_json 안의 식별정보를 가린다. **패턴은 유지, 식별자만 치환.**
- **가림:** 직원 실명 → `직원A`, 실제 파일명 → `[문서]`, 정확한 목적지 주소, **실제 개인정보 값(주민번호 등 절대 미전송)**, 정확 시각 → `야간` 등.
- **남김:** 위험 신호 패턴(위장·야간·채널교차·스크린샷 급증 등), 개수/카운트(값이 아니라 신호).
- 예: (로컬) "김철수가 영업기밀.xlsx를 위장해 23:10 메일+USB 반출" → (외부) "직원A가 [문서]를 위장해 야간에 여러 경로로 반출".

## 4. 프로바이더 신뢰 등급 [확정]
| 프로바이더 | 데이터 |
|---|---|
| 로컬(Ollama) / 사내 LLM | 풀 데이터(실명 그대로) — 나가지 않으므로 |
| 외부 클라우드 API | **마스킹 강제** |

## 5. 확인 필요 / 구현 메모
- 프로바이더 어댑터 인터페이스: `summarize` / `extract_slots` 계약을 프로바이더별 구현으로 분리(기존 `ollama_client` 확장).
- 마스킹 로직: signals_json에서 식별 필드 목록 정의 + 치환 함수(로컬/외부 분기).
- 1차 방어: 실제 개인정보 값이 signals_json에 애초에 안 담기게(카운트만) 설계.

## 참고 (확정 요약)
- 다양성 제공 + 기본 로컬(무유출) + 외부는 고객 책임 + 마스킹 안전장치
- 불변식: AI엔 집계 신호만(원본 미열람)
- 외부 = 마스킹 강제, 로컬 = 풀
